## 3. Row joins, weights, masks and preprocessing

The frozen IDs/splits and 25-category order come from the accepted shared data plan. FIT has 2,160 images and DEV-S 180; source-language/visual systems have one row per image. Pooled E03 has four context rows per image. Read categorical IDs as strings, join by image ID and preserve the source record/view keys and target-file hash. Validate exact rows/order, features and masks before any reuse.

The known mask determines the supervised rows independently per category. An unknown value is never a zero. Do not remove zero-feature rows, rare categories or high-loss images. A head requires both outcome classes and positive total known training weight; otherwise mark it unestimable with counts and no fabricated coefficient/probability. The fixed primary cohort remains 14 categories; all 25 statuses survive every artifact. No metric averages over a changing primary category set.

Use sample weight 1 for each source-language or image-only row and 0.25 for each pooled E03 context row. Every known image/category has total pooled weight one. No class weighting, oversampling, positive-label balancing, language-conditioned priors or extra duplication. Scaler statistics use all declared source-FIT input rows with these image weights, independent of category labels; masks only restrict the corresponding head's loss. This one label-free scaler is reusable across all C values, categories and true/random target assignments for that exact input/weight recipe.

Compute weighted means and population variances in float64 using a stable two-pass/weighted sparse routine. Fixed numerical rule: clamp only negative roundoff variance to zero; if variance <= 1e-12 set scale=1, otherwise scale=sqrt(variance). Record means, variances, scales, threshold, weights and exact fitting row hashes. Do not drop a column or fit variance on development/evaluation inputs. Test a sparse/dense-equivalent example including constant/near-constant columns and pooled-view replication.

Dense VLM/length inputs use (x-mean)/scale. Sparse TF-IDF stays sparse and uses x/scale, with centering=false explicitly recorded; an unpenalized intercept accommodates the coordinate shift. No dense conversion of TF-IDF and no additional row renormalization, PCA, feature selection or whitening. The source scaler is applied unchanged to any later receiving context. Different language vocabularies remain different bases.

Stage 2 matrices stay immutable float32. Fit/selection calculations and stored coefficients/intercepts are float64; use canonical source preprocessing then matrix-times-coefficients for logits. Store the center flag. If raw-basis weights are later derived, dense b_raw=b-mean dot (coef/scale), sparse b_raw=b; these cheap algebraic derivatives are not another fitted system or a reason to duplicate every cache. Validate the chosen score path; do not mix normalized/raw coordinates between sites or models.

## 4. Objective, optimizer and selection

For known rows of a category, the frozen objective is

J(w,b) = sum_i a_i [logaddexp(0, x_i dot w+b) - y_i(x_i dot w+b)] + ||w||^2/(2C).

The intercept is unpenalized. An equivalent mean-loss form divides both terms by S=sum_i a_i, giving penalty ||w||^2/(2 C S). Never normalize pooled weights to another total or substitute mean loss + ||w||^2/(2C) while claiming the same C. The selected scikit-learn 1.6.1 LBFGS implementation uses this sample-weight/C convention: [logistic implementation](https://github.com/scikit-learn/scikit-learn/blob/1.6.1/sklearn/linear_model/_logistic.py), [weighted loss/intercept implementation](https://github.com/scikit-learn/scikit-learn/blob/1.6.1/sklearn/linear_model/_linear_loss.py). These sources support the normalization/intercept semantics; the following tolerance, retry and selection choices are project policy.

Use independent sklearn binary LogisticRegression fits: solver=lbfgs, penalty=l2, fit_intercept=true, class_weight=None, tol=1e-8, max_iter=1000, warm_start=false, and the four fixed C values in ascending order. Verify class ordering [0,1] and positive-is-present coefficient orientation. Dense/CSR input and arithmetic are float64. Freeze the existing CPU profile (numpy 2.1.3, scipy 1.18.1, scikit-learn 1.6.1) plus actual Python, BLAS/threadpool and remaining versions at job creation. A changed numerical environment gets a different fitting identity.

One deterministic retry from the same zero initialization at max_iter=5000 is permitted for a convergence warning or exhausted iteration limit; objective, C, tolerance, rows/weights and solver do not change. Log both attempts, elapsed time, iteration counts, warnings, finite checks and objective/gradient diagnostics. Other solver errors block immediately. A nonconverged required head after retry makes that candidate block incomplete/blocked, never a success with a silently omitted category. Do not switch solver/precision/tolerance based on scores. A further policy change requires a new pre-outcome fitting specification and identity.

Each C block stores its source-DEV-S logits and per-category AUROC, AP, Brier/log-loss diagnostics and estimability/support. AUROC/AP use logits to avoid sigmoid saturation ties; probability metrics use stable float64 sigmoid/log-loss calculations. No DEV-S label influences FIT statistics or fitting. C selection uses primary-cohort macro AUROC only, with all 14 required categories defined. For pooled E03, first calculate AUROC separately for each category and each of the four DEV-S contexts, then average the 56 values equally; pooled captions are not independent images. Source-language/visual systems average their 14 values. These rules are identical for true and randomized targets.

Select one C for the whole 25-head system, not separately by category. If candidate score is within 1e-12 absolute of the highest score, choose the smallest C among those candidates. Missing primary metrics or required failed fits block selection; do not make a candidate look good by shrinking its average. Freeze all four candidate scores, tie decisions and selected block reference. A selected system is a reference to the original FIT-only fitted weights/scaler; do not refit on FIT+DEV-S. Keep all fixed depths and poolings; do not select a SCREEN-winning layer or pooling arm. No separate layer winner is needed for Stage 3's complete profiles. Stage 4 single-depth E19/E25 use the already fixed midpoint and default last_caption site.

FIT-prevalence probabilities and always-absent decision references are stored with counts/known weights, not masqueraded as trained heads. Fit prevalence uses known source-FIT weights only. Accuracy alone is not a validity or signal criterion under this imbalance.

## 5. Full G0 target assignments and diagnostic gate

Preserve three independent predetermined image-level assignment seeds 0,1,2. For each eligible partition separately, sort its canonical image IDs and sort donor IDs by SHA256 of the UTF-8 string `G9Q6-G0-label-v1|SEED|SPLIT|DONOR_IMAGE_ID`, lexical ID tie break. Recipient ID at position j receives the donor's entire original 25-value vector and its known mask. Record every recipient/donor pair. This deterministic recipe is defined before outcomes and has no per-language/model/feature dependence. Ordinary fixed points are retained/logged; do not reroll or force a derangement.

Generate assignments for FIT, DEV-S and SCREEN only in Stage 3. CONFIRM is excluded; DEV-C is not needed by this gate. Within a seed/partition all language views, pooled E03 views and models of an image receive exactly the same control vector. Never permute each category independently, shuffle rows without masks, permute across partitions or use a matching test image's training label. Preserve marginal class support/co-occurrence at image level. Source images/features are unchanged, and original labels remain immutable in their own namespace.

For every ordinary system and each of the three target assignments run the same four-C fitting/selection pipeline, reuse the exact label-free source scaler, and select C on that seed's source-DEV-S control labels. Using the ordinary selected C for all controls would omit the selection mechanism; it is not the matched primary gate. Cache every control candidate just like true candidates. Repeated optimizer seeds are not independent scientific samples and no extra optimizer-seed grid is scheduled.

After selection is frozen, generate each control system's within-training-context SCREEN logits once, against its SCREEN control targets. These are control-only scores, never ordinary scientific predictions. For pooled E03 keep all four contexts and group by image. Save per-category AUROC/AP/proper scores, macro values, class/mask counts, FIT priors and undefined reasons. Zero or negative discrimination is not automatically a failure; chance AUROC is not expected to equal exactly 0.5 on every finite sample. Random-control outcomes are diagnostics, not extra experiments or proof of genuine task relevance.

Structural checks are hard gates: exact source/target identities and grouping, no cross-partition overlap/CONFIRM processing, correct shared assignments, correct masks, identical preprocessing/weight normalization, converged estimable fits, finite scores, role enforcement, source-only selection and source-scaled transfer test fixtures. Any violation blocks acceptance and scientific interpretation.

The statistical anomaly screen is predeclared as one conditional global randomization test, not thousands of unadjusted pass/fail tests. Family: all selected randomized-target systems, all three seeds, each of the 14 primary per-category within-context SCREEN AUROCs and their declared macro; for pooled E03 include each context's category/macro values and the equally averaged context macro. Statistic: the maximum absolute deviation from 0.5 across that entire fixed family. Given fixed fitted/selected scores, create 1,999 further within-SCREEN whole-vector/mask permutations per control seed; use the same reassignment per seed/draw across methods/models/languages. Donor order is SHA256 of `G9Q6-G0-null-v1|DRAW|SEED|DONOR_IMAGE_ID`, lexical ties. No heads are refitted for this step. Compute the same global maximum on each draw. Global p=(1+number of null maxima >= observed maximum)/(2000). Flag p<=0.01 for automated pipeline investigation and withhold substantive interpretation until resolved; keep the original result and version any repair. Never reroll seeds to get a pass.

This conditional max statistic accounts for the declared search family/dependence through common image-vector reassignments. It is a diagnostic global-null screen, not per-category significance, a guarantee of no leakage, or paper-level confirmation. Its finite resolution/power and rare/undefined secondary targets are reported. The 11 secondary categories retain descriptive control results; they do not silently enter the primary max family. At the current full support all primary AUROCs must be defined; unexpected undefined primary results block the gate rather than changing the family. The G0 randomization count is distinct from the existing 2,000 paired-image bootstrap draws for later scientific uncertainty.

Cache ordered score/target IDs and null-draw recipes once. Calculate AUROCs from cached ranks where masks permit, with exact tie/mask handling and equality checks against the reference metric. Vectorize/batch diagnostic evaluation without changing its family or dropping views. Persist null maximum arrays and accepted per-block diagnostics; do not store another full prediction tensor for every null draw. No extra human semantic verification is a repair path. Numerical flags trigger traceable code/identity/solver debugging, not claims that a research direction is disproven.

For efficient distributed evaluation, a partial null block binds its exact source-system/seed subset, draw IDs and score/assignment hashes. Read a group's cached scores once and evaluate its fixed draws in bounded batches; retain partial maximum arrays for later merging. The final reducer takes draw-wise maxima only after verifying complete nonconflicting coverage of the frozen family and common draw recipes. It never averages per-worker p-values or treats missing groups as zeros. An incomplete family cannot publish the global gate. This permits resume/reuse without repeatedly reading every score file for each draw block.

## 6. Efficient reuse, memory and checkpoint policy

PHASE1_ROOT remains the persistent Drive phase1 root. Stage 3 reuses Stage 2 raw features and E03 preprocessor artifacts without reopening raw images, redownloading weights or revalidating every original image/archive on every fit. Validate the accepted numeric artifacts, row/target/mask references and hashes at the producer/consumer/resume boundary. Stage 2 artifacts must not be modified or their integrity helpers weakened to make this faster.

The coordinator owns an in-process verified numeric session. It verifies complete releases/children at open, loads or stages their needed numeric arrays once, and retains immutable bytes/matrices or private read-only memory maps tied to those hashes. Cheap split/role/source/context checks run on every access. Cached views never change permission. A fresh process/resume fully verifies consumed inputs again; an old pathname alone is not a verified session. If retaining verified arrays is infeasible, use bounded per-release/site/group sessions and reread at that boundary, not per category/C. Existing public verification routines can be composed in a Stage 3 loader; workers must not independently bypass them or use unchecked raw .npy files.

Process one feature-system group at a time. Its FIT/DEV-S arrays and one transformed float64/CSR working copy remain in memory for the category/C/assignment loop. Persist only the small source statistics as a shared preprocessing artifact. Do not write another complete standardized copy of all Stage 2 matrices to Drive by default. Different scripts may reload immutable input arrays, but must reuse fitted source statistics and every compatible completed fit; they do not refit just because they are separate scripts.

Checkpoint unit is one complete C block: all 25 category outcomes, weights/intercepts, source-DEV-S predictions, metrics and convergence records. Publish payloads/marker once at block completion, not per head/iteration or every log line. After all four Cs, publish one immutable selection index referencing those blocks. Persist randomization results in deterministic blocks of 100 draws (last smaller), plus one final gate receipt. Store final per-group/inventory manifests at completed group/partition boundaries and on a handled failure if useful progress exists; do not rewrite a growing full-job index after every category. Print exact latest completed references for explicit restart. Lost partial work is bounded by one C block or 100-draw block; do not promise zero model-load/partial-block recovery cost.

Only verified completed compatible artifacts can be reused. Partial/failed attempts stay non-consumable and immutable; write a new unique attempt for missing work. Deterministic duplicate equality is checked at canonical numeric content level, retaining original provenance. An input/solver/source/precision change creates a different fitting identity; a metric/plot/CI change does not invalidate raw features or unchanged fitted heads. Cross-environment reuse requires the recorded compatible numerical implementation; do not quietly merge slightly different coefficient solutions under one identity. No newest-file discovery, overwrite, concurrent append log or shared mutable global checkpoint.

Default execution is one active fit process and one BLAS/OpenMP thread per worker; resolve thread limits before numerical imports and record actual limits. Models and E03 may run concurrently on distinct CPU runtimes with separate job ownership; no GPU is needed. Within one runtime additional processes must have explicit disjoint blocks, remain within an upfront memory budget and use one BLAS thread each. Thread-count changes are recorded in fitting identity and must pass the numerical-equivalence fixtures before production. Do not promise parallel speedup on shared Drive or oversubscribed Colab CPUs.

Before bulk fitting, process the first canonical source system's C=0.01 true block and seed-0 block as actual production units, checking formulas, convergence, serialization/reload, source-scaler score equivalence, memory and elapsed read/fit/DEV-S/write/verification time. Continue from these completed units, not a score-selected pilot or another sample split. Publish projections from measured dimensions/nonzeros and the exact remaining block inventory. A cheap independent length recipe fixture is a software test, not a timing substitute for wide VLM/TF-IDF jobs. Report dimension-dependent estimates and peak memory; no fixed runtime guarantee follows from Stage 2 timing.
