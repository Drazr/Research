## Scoring worker

Public imports are in `src.stage4.interfaces`. Open the plan once with `load_stage4_plan(root, protocol, manifest)`. A manifest can be a completion path or an explicit `{"path": ".../_COMPLETE.json", "sha256": "..."}` relative reference. The plan validates the registry, its independent readback inventory, the G0 gate, and ordinary selections. Using the current pinned source tree keeps compatibility with Stage 3's audited budget amendment. Reuse accepted Stage 3 weights and scalers and Stage 2 numeric features through the scorer.

- `scoring_blocks(plan, owner)` returns ordered block IDs for `qwen`, `gemma` or `e03`. Priority 0 is the E01 midpoint SCREEN grid and DEV-C diagonals for that model. Publish those blocks first. There are 70 blocks each for Qwen and Gemma and 13 for shared E03, covering 529 SCREEN and eight DEV-C route slots.
- `score_and_publish_block(plan, owner, block_id, producer)` authorizes one block before I/O, reads verified target arrays once for all its source heads, and publishes canonical float64 logits with row, release, readout and scaler provenance. Return and stream its explicit completion reference. Stage 4 code owns DEV-C/SCREEN authorization. Stage 3's public split guards remain in force.
- `load_prediction_block(plan, ref, expected_block=...)` returns a route-ID dictionary of immutable predictions. Each exposes `reference`, `route`, `split`, `rows`, `logits` (rows × categories), `estimable` and `prevalence`. Mask unestimable heads before interpreting their numeric padding. Use `prediction_index(plan, refs, required_blocks=...)` for explicit resume inputs, then process only missing owned blocks. Reject foreign ownership and conflicting duplicate block identities.
- Stream completion refs as work finishes, including the priority release handoff. Save coarse completed blocks under the coordinator-created parents. On interruption, merge exact explicit references and validate reuse rather than discovering arbitrary directories. Report measured read/hash, score, write, readback and memory costs from the first scheduled production blocks. Each source array can be reused across routes within the same block. The shared store bounds verified-byte caching.

## Analysis workers

`analysis_units(plan)` returns the 47 frozen work units keyed by `E##/owner/part`. Filter by assigned experiment and owner before execution. Units are split by fixed depth for E01/E02/E04, with an E02 visual unit, by source in E19, by fixed source or diagonal comparison in E25, and by shared absolute or model comparison outputs in E03. A unit exposes `required_blocks` and a mapping `comparisons` from stable comparison IDs to descriptors.

- Resolve every descriptor's ordered `inputs` via its exact block and route IDs. Most pair deltas use arm 1 minus arm 2. Transfer gaps use diagonal minus transfer for higher-is-better metrics and transfer minus diagonal for Brier/NLL. E02 transfer-gap change subtracts the caption-only gap from the combined-input gap. E03 `view` selects the named caption context, while `pooled_context_mean` equally averages its listed views. E25 uses the descriptor's `label` stratum, retaining label-free rows when the label is null.
- `targets_for_prediction` returns boolean category labels and known-cell masks in row order. `paired_image_alignment(plan, *predictions, contexts=...)` returns shared sorted SCREEN IDs and per-arm row indices. For pooled E03 pass a language selector as needed. Apply the same known-cell support to both arms. Paired outcome inference and E19/E25 definitions are fixed in the contracts.
- `load_bootstrap(plan)` returns verified shared image indices in `plan["screen_ids"]` order. Convert once via `bootstrap_counts(draws, len(screen_ids))`. `binary_metrics(y,p,known)` returns point statistics and counts. `bootstrap_binary_metrics` uses row multiplicities and returns arrays with undefined draws represented by NaN. Apply `fixed_macro` over the same 14 indices in each draw and `bootstrap_interval` to paired outcomes. For E25 use `association_orders(category_id, label, sorted_image_ids)`, retaining only permutation recipes, membership identities and summaries. For E19 use `confidence_cutoff(p, nominal)` and apply the returned cutoff to all SCREEN arms using the include-ties comparison.
- `required_rows(plan, unit)` returns the minimum exact keys `(comparison_id, category, statistic)`, including `primary_macro`. Each tidy row has those keys as named fields, plus `value`, `status`, `reason` and `support`. Category support records the known, positive and negative counts for the declared evaluation cohort, and additional metric denominators alongside those counts. E25 strata use their true-label membership, E19 source coverage uses DEV-C, and E19 target results use the SCREEN cohort with retained counts recorded separately. Macro support describes the category cohort. Paired estimable rows carry `interval` with lower/upper and valid/total draws. Persist undefined values as JSON null with a reason. Descriptor lineage and status records accompany these tables through the release.
- `publish_analysis_block(plan, unit_id, prediction_refs, rows, producer, cutoffs=...)` verifies exact prediction inputs and the required result inventory. `prediction_refs` is a block-ID to completion-reference dictionary for that unit's exact dependency set. For E19 provide one cutoff row for each baseline, category and coverage in that source unit. Include `baseline`, `category`, `nominal`, `eligible`, `retained` and `cutoff`. The coordinator independently checks those records against DEV-C. For other families omit cutoffs. `load_analysis_block` verifies a previously completed unit for resume. Reuse only if its inputs match the explicit inputs of this run. Publish complete bounded units and stream references and timing.

Planned limits on optional E04 arms are recorded in final release coverage. Keep all 25 categories and support statuses in the scheduled tables. Before reporting a result, retain the paired comparison and inference boundaries in `prelim.md`.

E25 passes `memberships=e25_memberships(plan)` to `publish_analysis_block`, with the same sorted known-label image IDs used to build permutation orders. Use the shared support counts for every pair. For a primary macro of the null overlap, average the fixed category terms within each permutation before taking quantiles. Record label-stratum and conditional-event support separately. E19's category AUROC/AP is based on the underlying category predictions across eligible SCREEN cells.

## Coordinator run and Stage 5 handoff

In Colab use CPU, configure cell 3 and execute cells 2 → 3 → 4. Run `prepare_stage4.ipynb` with the explicitly accepted Stage 3 final registry. After all workers complete, run `validate_stage4.ipynb` with the prepared Stage 4 plan and an inventory JSON containing `predictions` and `analyses` lists of explicit completion references. Supply one reference per frozen block or analysis unit. The validator checks coverage, score row/selection/scaler provenance, analysis dependencies, cohort support, E19 cutoffs and each artifact checksum. It then launches independent readback and publishes an accepted Stage 4 release. Stage 5 calls `load_stage4_release(plan, reference)` and consumes the released table and prediction pointers. Keep the original production guard in place for fixture development and defer final integration and acceptance until the worker outputs exist.
