# Stage 5 worker handoff

Branch from the first commit adding this file. The coordinator owns `src/stage5/interfaces.py`, `coordinator.py`, `operations.py`, the synthesis and validation notebooks, and foundation tests. The model worker owns `src/stage5/run_model_report.py`, `scripts/stage5/run_model_report.ipynb` and `tests/test_stage5_model_report.py`. The E03 worker owns the corresponding `run_e03_report.py`, `run_e03_report.ipynb` and `test_stage5_e03_report.py`. Add worker-specific display code only in your owned files. Coordinate shared changes before editing.

## Worker API

- `open_release(root, protocol, reference) -> ReportRun` requires the exact `{"path": ".../_COMPLETE.json", "sha256": "..."}` from the successful Stage 4 validator. It opens the plan through the existing Stage 4 loader and requires the accepted release and matching independent readback. There is one common release for all workers.
- `publish_owner_report(run, owner, producer, *, resume=None, progress=None) -> dict` loads the owner's accepted tables, resolves route metadata and publishes the canonical immutable report. Invoke `current_producer(storage_scope)` from the same interface. Use `qwen` or `gemma` with one model selector, and run `e03` once without a model selector. Emit the returned reference as JSON and forward progress events with flushing. Resume accepts an explicit previous reference, verifies the exact content and requires the same producer commit.
- Canonical report bodies use `stage5.owner_report.v1`. They retain one table per accepted owner unit (23 per model, one for E03), with original comparison descriptors, prediction and analysis references, rows, E19 cutoffs and E25 association membership hashes. Route entries provide split, source/target contexts, condition, physical site and zero-based scheduled depth role, plus the accepted selection/candidate reference. The report carries the fixed SCREEN images, categories and primary cohort. Fit, scaler, model revision and feature provenance are traceable via the accepted prediction/registry/suite lineage. Use the report body for display. Keep full rows and support flags. The shared E03 unit includes its pooled context macro, and the per-model E03 units carry neural-minus-shallow comparisons. Do not create a second canonical table cache or read numeric feature/prediction payloads for formatting.

Use CPU, the existing pinned CPU environment and a clean detached checkout at the integrated commit. Keep setup, settings and execution separate. Publish to `PHASE1_ROOT/results/stage5/reports/<owner>/`. Each runtime owns its report. Production requires the actual Stage 4 accepted reference. Fixture development can start without it.

## Coordinator execution

1. Run the model worker for Qwen and Gemma and the shared E03 worker on CPU. They may run in parallel. Keep their three returned references.
2. Run `scripts/stage5/synthesize_stage5.ipynb` once with the Stage 4 release and a JSON object keyed by `qwen`, `gemma` and `e03` whose values are those references. It verifies exact coverage and matches scheduled comparison designs across models using route, pooling, condition, depth role and comparison policy. The resulting `paired_views` indexes aligned comparisons in the owner tables. Use the two models' original rows and intervals side by side. The index does not compute a cross-model effect or bootstrap interval.
3. Review the aligned evidence, absolute baselines, contrary findings and support using `plan.md` §5.3–5.4 and `prelim.md` §§8–9. Use a JSON object with a substantive `summary` and a `decisions` list. Each entry has `id`, `question` (G9, Q6 or G9-Q6), `scope`, `finding`, `disposition`, `alternatives`, `next_uncertainty`, `decision_change`, `next_test` and `evidence`. Use the four dispositions from the plan. Set `next_test` to `{"test": "...", "dependencies": "..."}` for retain/revise and null otherwise. Every evidence item specifies `unit`, `comparison_id`, `category` and `statistic` from an owner table. Keep an empty decisions list only when the summary explains why no direction is supportable. Research review uses the existing outputs and involves no additional annotation or manual dataset verification.
4. Run `scripts/stage5/validate_stage5.ipynb` once on CPU with the Stage 4 release, synthesis reference and review file. It resolves each citation to an exact immutable row, verifies the report bindings and publishes the final bundle with fresh readback. Software validation checks structure and provenance. The review remains responsible for the scientific interpretation. Local fixture outputs always carry `stage5_complete=false`.

Stage 5 uses accepted analysis values and metadata. Leave CONFIRM closed and keep new fitting, calibration, extraction, statistics and follow-up experiments outside these entries.
