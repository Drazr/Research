## Working preferences and lessons

**Scientific goal.** Preliminary work narrows questions for a focused study. Favor comparisons whose result could change which direction survives, with adequate support, interpretable controls and an uncertainty that is already present. Keep several strong directions if the evidence warrants them. A third preliminary phase is optional and the maximum. Use it only for a decision the current results cannot settle. Complex mappings, learned confidence and systematic competing-explanation studies should earn their cost through evidence. Record a reason and traceable result for every decision to retain, revise, park within scope or mark unresolved.

**Data and claims.** Use the released image-category labels with the original English, Hindi, Bengali and Telugu captions. Labels are shared by image, and native captions may differ in content as well as language. Compare on matched known image/category cells and resample by image. Preserve the splits and existing unknown cell. Keep the fixed 14-category primary macro where estimable, and label support restrictions and changed cohorts explicitly. Keep CONFIRM closed. No human annotation, translation checking, review of caption meaning or manual dataset work. Treat SCREEN reuse as exploratory. Confine claims to the diagnostic readout. Separate accessibility, transfer, ranking, probability quality and correctness. Distinguish source-only transfer, adaptation using target FIT inputs and calibration using target DEV-C labels.

**Phase 2 execution.** E29 starts from accepted SCREEN logits. E17 can start independently once added DEV-C scoring is authorized. Its target arm uses the same frozen source head on the target DEV-C view. E07 first checks original-caption availability and support, then runs only changed SCREEN views with last-caption and caption-mean collected on the same forward. Fixed-head evaluation comes first. Any additional refit changes the estimand and needs its own decision. E30 and E11 each take their own E29 result as a gate and may run in parallel if both qualify. E30 already has its matched arms in Phase 1. E11 reuses matching FIT statistics where identities agree. Reuse one draw-0 score reference, one paired image bootstrap definition and common scoring/metric helpers wherever the exact joins and comparison recipes agree. Freeze the proposed effect thresholds and contrasts before opening new SCREEN results.

**Runtime and notebooks.** Prefer CPU with the tested Python 3.12 pinned CPU environment for validation, scoring, summaries and analysis. Use the accepted L4 GPU configurations only for E07's new Qwen/Gemma forwards. Give all model-dependent entry points one explicit `MODEL` variable so a single notebook can run in separate sessions for Qwen and Gemma. Shared work runs once. Keep setup, settings and execution cells separate, with one visible settings cell. Check the pinned checkout and notebook runtime. A shell-level subprocess error can hide the useful cause, so stream output and report the worker's actual blocker. When accessing gated Gemma weights, use the existing authorized `HF_TOKEN` Colab secret in that session. Verify actual Git and Python paths in Antigravity before making changes, since another agent's PATH may differ.

**Storage and speed.** Phase 1 long runs were dominated in places by repeated Drive reads and repeated validation. Verify explicit references and hashes at producer, consumer and resume boundaries. Reuse verified reads within a bounded session and avoid rescanning unrelated arrays or rerunning full validation as a prerequisite for every branch. Initialize shared output parents once before concurrent writers. Choose and document a distinct persistent Phase 2 output namespace with exact Phase 1 input pointers. Share immutable completed feature/score blocks, calibration parameters and other genuinely expensive reusable results. Checkpoint meaningful completed units where interruption would cost time or another task consumes them. Keep cheap intermediates and plotting inputs in memory. Stream progress with the current unit, completed count and read/compute/write timings. Scope artifact identities to the inputs and recipe they depend on, and make resume reject incompatible checkpoints.

**Chat coordination.** Plan one stage at a time. Freeze shared interfaces and tested base commit before splitting work into worker chats. Assign disjoint file ownership and use isolated branches/worktrees where useful. Return each branch, commit, files, fixture checks, production prerequisites and exact handoff references. A fixture pass or a copied notebook is software evidence. Mounted Drive, checkpoint access, actual L4 execution and production acceptance should be reported separately. Keep a short running record of decisions, actual artifact references, failed assumptions and the next runnable step for the return handoff.
